# Plan: content team motion and sound (gaisser-agents 4.7.0)

## Handoff

### Goal
Upgrade the content team so a vertical reel can carry licensed music with cuts on detected beats, three.js postprocessing and particles that stay deterministic, and scenes made with the user's optional design skills (hairline, anatomy, anatomy-reveal), while the GSAP + `window.__seek` + frame capture + ffmpeg pipeline stays the base. QA gains checks for audio licence and beat sync and for pre-rendered scenes. Version 4.7.0.
Revision R1: the installed design skills are the designer's craft foundation on every piece, not a menu. Their principles are distilled once into a cached per-project craft digest, every spec maps each scene, transition, coded graphic, ease, and page to digest principles in `## Craft sources` under minimum coverage rules, and QA check 10 verifies the mapping against the render.
Revision R2: static and page design get the same foundation.
- The content designer gains a layout guide (`references/layout-craft.md`, `LY-` rules) and a digest that also covers installed layout and UI skills.
- It must run one critique pass against the scout's references before the final render, and stills get a layout report.
- QA check 11 measures grid alignment, type-scale steps, rag and widows, sticker anchoring, and sequence variety.
- The product team's UX designer gets UI craft rules (`references/ui-craft.md`, `UI-` rules), a design-token contract, a rendered critique of key screens, and a visual contract the product reviewer checks with text search.
- Budget: at most +10-15% per piece over the pre-4.7.0 baseline, R1 included.

## Design decisions and trade-offs

1. **Design skills are optional, read-only inputs.** The orchestrator finds them once per run (tool preferences folder first, then `~/.claude/skills/<name>/SKILL.md`, then `~/.agents/skills/<name>/SKILL.md`), records the found paths in `run.json` `designSkills`, and passes them; the designer reads them with its read tool and runs their scripts with the shell. A missing skill is skipped and named in the spec. Rejected: vendoring the skills (licence and drift), naming absolute paths (public plugin), a skill-invocation capability (the build has none and Codex differs).
2. **Two integration modes.** Default for reels: *scene* mode, where the skill's output is pre-rendered to a PNG sequence at the reel's fps and shown by an `<img>`/canvas whose frame `__seek(t)` picks, with brand type and stickers on top in the GSAP page. *Own render path* only when the skill's film is the deliverable (an anatomy-reveal product film). Rejected: `<video>` seeking (frame-inexact) and iframes driven live (non-deterministic).
3. **Which skill when (superseded by 10 and 11 in R1; kept only for choosing a renderer for an optional pre-rendered scene).** hairline-create for one software idea (fastest); hairline-adopt only for the user's own SVG; anatomy for a system explained as a machine (Figure size, about an hour); anatomy-reveal for physical setup objects (hours, so the orchestrator states the estimate at the brief); motion-design as principles for any video, below the team's `motion-design.md` and the visual system on conflict; motion only to design spring curves, converted from its CSS `linear()` stops into a GSAP ease function, never CSS animation.
4. **Live pages are captured on a virtual clock.** hairline and anatomy pages run on `requestAnimationFrame`; Playwright's `page.clock` fakes `requestAnimationFrame`, `performance`, `Date`, and timers, so `install` then `runFor` per frame gives repeatable frames. anatomy-reveal is already seekable through `window.frame(t)` and keeps its own renderer (motion blur).
5. **Remotion: optional, off by default.** Its licence is source-available, free only for individuals, for-profit organisations of up to 3 employees, non-profits, and evaluation; others need a Company License (Creators 25 USD per seat per month, Automators 0.01 USD per render with a 100 USD monthly minimum). A public Apache-2.0 plugin cannot default to that. It also duplicates the GSAP pipeline whose QA contract (`data-copy-id`, `layout-report.json`, checkpoints) is DOM-based, and its strongest features (captions, voice) are unused here. Allowed only when tool preferences name Remotion for a format and record licence eligibility; the same outputs contract then applies. This user (an individual) is eligible.
6. **Sound sourcing by the scout, analysis by the designer.** The scout already has web access and shell, downloads into `scout-refs/`, and records licences of `candidate-asset`s; the designer has no web and stays offline except package installs. The orchestrator resolves the new media class `stock-audio` and writes `assets.md`. Licences: only `cc0`, `pdm`, `by`: under CC 4.0, syncing music to moving images always creates Adapted Material, so `nd` forbids it, `sa` would force the reel under the same licence, and `nc` conflicts with brand content. A class missing from the user's policy resolves to `ask`.
7. **Beat detection is a small script shipped as a fenced block** in `audio-beats.md` (skill files cannot be `.py`); the designer copies it to `code/<piece>/audio/beats.py`. librosa 1.0.1 (12 Nov 2026) requires Python 3.12 or later, lists 3.14, and ships a pure wheel; numba has had Python 3.14 wheels since 0.63 (Dec 2025). So the default is a 3.14 venv, then a `py -3.12` venv, then no beat sync. librosa 1.0 dropped audioread, so the excerpt is first converted to mono WAV with ffmpeg, which also fixes the time origin: analysis and mix use the same `-ss` offset.
8. **No CHANGELOG.** None exists; starting one at 4.7.0 gives a partial history and one more file to keep in sync. Release notes go in the PR description. Open question for the user.
9. **QA grows to nine checks** rather than folding audio into checks 5 and 7, so an audio or scene failure routes cleanly (licence to the main session, sync and scenes to the designer). A piece without audio or scenes records `pass` with "not applicable".
10. **R1: one craft foundation, distilled once into a cached digest.** Reading every skill each run is too heavy: motion-design alone has 18 files, anatomy's `craft.md` and `motion.md` are long, and the Remotion tree has about 150 files. The designer instead keeps `team-context/content-team/craft-digest.md` in the user's project: a fixed file list per skill, principles paraphrased in one line each with a stable ID (`MD-` motion-design, `MO-` motion, `AN-` anatomy, `HL-` hairline, `AR-` anatomy-reveal, `RM-` remotion-markup), how each shows in a frame, the source file, and a per-skill fingerprint. At the start of every run the designer recomputes the fingerprints with the shell (hashing only, no reading) and rebuilds only the sections that are missing or changed. A normal run then reads about 150 lines instead of tens of thousands. It sits in team-context because it is per-user knowledge reused across runs, like the visual system, and the run folder would lose it. The designer writes it, because it is the role that applies it and has the shell; the brand role has no shell and owns brand facts, not craft. Rejected: reading everything every run (context cost); a digest shipped in the plugin (it would copy third-party skill content into a public repository and go stale); a digest per run (no reuse).
11. **R1: coverage rules plus an independent check.** A mapping with no minimum would be decorative. Each scene needs at least one Disney principle and one timing or choreography rule (`MD-`). Each named transition has an ID, and every video has at least one from the reveal vocabulary (`AR-`: tumble in, whip to macro, explode, snap back, hero hold). Every coded illustration, icon, diagram, or figure follows `AN-` or `HL-` rules (isometric construction, four-tone shading, painter's order, lines that resolve, one accent stroke, composed rest pose); type, plain shapes, and gradients are exempt. Every spring or overshoot ease is an `MO-` curve converted to a GSAP ease. At least one `RM-` rule shapes the timeline structure (sequencing, timing, transitions, motion blur on whips, text highlights) even though Remotion never renders. Stills apply `MD-` staging and hierarchy per page. The visual system and the team's references win on conflict, recorded in the digest's `## Conflicts`. A rule for a skill that is not installed is waived. QA check 10 confirms independently: every row exists, every ID is in the digest, the minimums are met, each row is `seen` where it says, and for at least 3 IDs QA reads the source file itself, so the designer never grades its own mapping. Pre-rendered scenes stay optional, because forcing one into every piece would add hours (anatomy-reveal) without being needed for the language to apply.
12. **R2 diagnosis: why the content pages look weak.** Evidence from `brazo-robotico-01` (6 pages) and the three carousels of 2026-10-10:
    - D1, one template on every page. Every page uses the same block at the same place and scale with the same scrim, so a carousel has no rhythm. The three later carousels copy the same `style.css`.
    - D2, stickers as leftovers. Badges, pills, and cards sit in whatever corner is free, at arbitrary x positions (740, 700, 648), relate to nothing in the photo, and use generic UI chrome (a `passing` badge, an `MVP -> feedback` pill) unrelated to the copy. In 2026-10-10 slide 3 a sticker covers the back of a person's head.
    - D3, line breaks never set. The spec says "I did not rebalance": widows (`duda.`, `sostenerlo.`, `equipo.`) and a stranded `de` (`un punto de / partida.`).
    - D4, no grid or rhythm. Gaps are 14, 26, 4, and 26 px with no baseline unit, and stickers align to no column.
    - D5, the composition ignores the photo. The text block sits on the subject or a busy screen (the kicker over a laptop UI), the scout's crop instructions were not applied, and one heavy scrim tuned for the kicker flattens the lower half of every photo.
    - D6, effort spent on measurement, not composition. The spec is rigorous on contrast and silent on hierarchy, focal point, and sequence.

    Root cause in the plugin: every designer reference is about motion (`motion-design.md`, `kinetic-typography.md`, `video-pipeline.md`, `visual-fx.md`). There is no static layout guide, Process step 2 asks only for a motion idea, QA checks contrast and clipping but nothing about layout quality, and nothing makes the designer compare its pages with the scout's 8 visual references. Separately, the brand rules themselves lean on several traits `frontend-design` lists as generated-design defaults: a cream and serif look with a warm accent, a tracked uppercase kicker, a middle-dot date string, and monospace labels. The visual system wins, so this goes to Open questions, not into the build.
13. **R2 mechanism for content (priority).**

## Risks and edge cases

- Openverse anonymous rate limits or downtime: the scout makes at most 10 requests; on failure the run goes silent and the report says so. Few permissive music results (a test query returned 39): broaden mood terms, then fall back to SFX-only or silence.
- Content ID claims on CC BY tracks re-uploaded by others: noted in `audio-beats.md`; prefer `cc0` when two candidates fit.
- pip install of librosa on 3.14 may still miss a wheel for a dependency on some machine: fallback chain; AC9 records the Python used.
- GPU nondeterminism in headless WebGL: the determinism check (two fresh renders, `magick compare -metric AE` = 0) catches it; on failure the designer drops the effect, not the check.
- three.quarks may call `Math.random`: the page replaces `Math.random` with the seeded generator before any system is created, and seeks backwards by rebuilding from the seed.
- `EffectComposer.render()` without a delta reads a wall clock and `FilmPass` accumulates time: always set time uniforms from `t` and call `composer.render(0)`.
- Pre-rendered scenes with their own words (hairline read-out, anatomy card captions) would fail text integrity: hide them with an injected style; every word comes from `copy.md`.
- anatomy-reveal's paper look may clash with the palette: treated as an image under the visual system's image treatment rules.
- `--plugin-dir` override is ignored if managed settings lock the plugin: the debug log check in AC16 catches it; fallback in Open questions.
- Test traps: the QA prompt's `ship.md` sentences and the `scout-research.md` minimum lines must stay verbatim.
- R1, first-run cost: building the digest reads about 40 files once (the Remotion tree is limited to 6 files). The designer reports `Digest: rebuilt`; later runs reuse it.
- R1, ID gaming (an ID pasted on everything): the "How it shows" column must name a property, value, and checkpoint, and check 10 fails any row that is `not seen` or that the source spot-check contradicts.
- R1, conflicts with the brand (anatomy's paper tones, hairline's monochrome stroke): the visual system wins, `## Conflicts` records it, and the principle still applies in form (construction, order, line logic), not in colour.
- R1, other skill versions with other file names: the digest reads the listed files that exist and records the list it used; a missing file lowers the minimum only if the skill's `SKILL.md` no longer names that topic.
- R1, prompt budgets: designer at 46 lines plus about 4 lines, QA at 39 plus about 2; both stay under 80.
- R2, rules that fight the brand: layout rules never move a brand value; when the visual system fixes the title block, variation comes from framing and the graphic layer (`LY-` sequence rule).
- R2, line breaks versus text integrity: a forced break is layout, not copy; QA check 1 compares `innerText` with whitespace normalised (stated in `layout-craft.md`), and the copy text never changes.
- R2, false precision in check 11: thresholds are tolerances (2 px grid, 30% widow), rotated stickers are measured by their unrotated box, and face boxes are the designer's own (as today).
- R2, Edge headless flags differ by version: `ui-craft.md` gives `--headless --screenshot --window-size`, falls back to the Playwright `channel: 'msedge'` route when it is installed, and to a code critique without screenshots, recorded as such.
- R2, budget overrun: one critique round, one board image, check 11 by script; if AC16's cost looks high, the first lever is a smaller digest.
- R2 prompt budgets: designer about 50 to 54 lines, QA about 41 to 43, product-ux 38 to about 44, reviewer 41 to about 43.
